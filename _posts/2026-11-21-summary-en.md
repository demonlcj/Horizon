### [Finite-time blow-up for the Navier–Stokes equations](https://github.com/tristanbuckmaster/navier-stokes/) ⭐️ 9.0/10

Tristan Buckmaster and Alpoge have proved finite-time blow-up for the unforced Navier-Stokes equations, a Millennium Prize problem. The result shows that certain smooth initial data lead to singularities in finite time with no external forcing term required. This distinguishes the work from a recent OpenAI demonstration that relied on a carefully engineered external force.

hackernews · trotro · Nov 20, 15:34 · [Discussion](https://news.ycombinator.com/item?id=50576232)

**「Navier–Stokes Existence and Smoothness Problem」** The Navier–Stokes equations, first written in 1822, are a set of partial differential equations that describe the motion of viscous fluids. The Clay Mathematics Institute selected the question of whether smooth initial data for these equations always produce smooth solutions for all time as one of the Millennium Prize Problems. This result establishes that finite-time blow-up is possible for the unforced Navier–Stokes equations.

**「Impact」** The proof supplies a counterexample demonstrating that smooth solutions to the Navier-Stokes equations need not exist globally, thereby resolving the Clay Millennium Prize Problem in the negative and clarifying that fluid singularities can arise even without external forces.

**「Community Discussion」** Hacker News commenters described the result as one of the most significant mathematical achievements of the day, placing it alongside the generalized Riemann Hypothesis. Several users noted the drama of potential scooping by OpenAI and Anthropic, while others expressed interest in physical simulations or real-world demonstrations to visualize the blow-up.

### [KVM Vulnerability Allows VMs to Read Host Memory on AMD](https://thehackernews.com/2026/11/new-linux-kvm-flaw-cve-2026-99312-lets.html) ⭐️ 8.0/10

Linux KVM has been patched for CVE-2026-99312, a vulnerability that allows virtual machines on AMD hosts with nested virtualization enabled to read host memory. The flaw was demonstrated by reading approximately 127 GB of host memory from a VM on DigitalOcean. The upstream fix is available in Linux kernel 7.3.5 and later versions, released on November 18; Debian and Ubuntu kernels have not yet been updated, and disabling nested virtualization is recommended as a temporary workaround.

telegram · zaihuapd · Nov 20, 14:23

**「Linux KVM Nested Virtualization on AMD」** Linux KVM is the virtualization module in the Linux kernel that supports running virtual machines, including nested virtualization where a guest OS functions as a hypervisor. The CVE-2026-99312 vulnerability stems from a stale pointer in the AMD-specific nested virtualization code within KVM, which had persisted for nearly four years and allowed a guest VM to read host memory when enabled. Intel-based KVM hosts are unaffected because the vulnerable code is exclusive to AMD&\#x27;s implementation.

**「Guest VMs Can Read Host Memory on Shared AMD Hosts」** On shared AMD hosts with nested virtualization enabled, a guest VM can read up to 127 GB of host memory, including other tenants&\#x27; VMs, enabling potential data exposure. Disabling nested virtualization via the kvm\_amd.nested parameter set to 0 closes this path completely.

### [Why Output Caching Doesn&\#x27;t Work in LLM Agents](https://seangoedecke.com/why-output-caching-doesnt-work/) ⭐️ 8.0/10

rss · Sean Goedecke · Nov 21, 00:00

**「Background」** In LLM-powered agent systems, caching model inputs prevents repeated computation of conversation history for each new message. Agents frequently repeat content like code snippets or evidence quotes in their outputs, raising the possibility that caching outputs could avoid wasting expensive output tokens.

**「Solution」** To cache outputs, the model would need to output references to prior segments rather than full repetitions, allowing the harness to expand them transparently. However, this approach only optimizes the visible output, which accounts for just 6% of total tokens based on agent histories—50% reasoning tokens and 44% tool calls. Applying Amdahl&\#x27;s law, even if you save two-thirds of the visible tokens \(optimistically\), you still save only about 4% of the overall output. The majority of tokens are invisible and already available internally, so output caching yields minimal gains. Instead, savings require reducing the 94% invisible tokens through more intelligent models that need less reasoning and tool use.

**「Takeaway」** Caching outputs won&\#x27;t meaningfully reduce costs in agent workflows since it targets only a small visible fraction; the key is using smarter models to minimize total token requirements for better efficiency.
