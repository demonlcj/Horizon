### [Finite-time blow-up proven for unforced Navier-Stokes equations](https://github.com/tristanbuckmaster/navier-stokes/) ⭐️ 8.0/10

Tristan Buckmaster and collaborators have proven finite-time blow-up for the unforced Navier-Stokes equations. The result shows that there exist smooth initial data for which the solution to the incompressible Navier-Stokes equations \(without external force\) blows up in finite time. This establishes a key case for the unforced problem, distinguishing it from recent forced examples and advancing the mathematical understanding of fluid dynamics singularities.

hackernews · trotro · Nov 20, 15:34 · [Discussion](https://news.ycombinator.com/item?id=50576232)

**「Navier–Stokes Millennium Prize Problem」** The equations are a system of partial differential equations that describe the motion of a fluid in space. Although computational solutions to the Navier – Stokes equations are used in a large number of practical applications, there is no complete analytical understanding of the solutions. The existence and smoothness of Navier–Stokes solutions is a Millennium Prize Problem.

**「Impact」** This theoretical result may affect the reliability of computational fluid dynamics simulations in software engineering and AI systems by indicating potential unphysical behaviors in fluid flows.

**「Community discussion」** Hacker News users point out that this unforced result is more realistic than OpenAI&\#x27;s forced Navier-Stokes example. Some commenters express interest in real-time simulations of the blow-up or physical demonstrations of the phenomenon.

Linux KVM exposes CVE-2026-99312, a flaw that lets virtual machines read host memory on AMD systems when nested virtualization is enabled. Researchers demonstrated the issue by extracting about 127 GB of memory from a guest VM on DigitalOcean. The upstream fix was released on November 18 in kernel 7.3.5, but it has not yet reached distributions such as Debian and Ubuntu.

**「Nested Virtualization in Linux KVM」** Linux KVM \(Kernel-based Virtual Machine\) is the kernel module that provides hardware-assisted virtualization, enabling multiple virtual machines to run on a single host. Nested virtualization extends this by allowing a guest operating system to run its own hypervisor, a capability specifically supported on AMD processors. This configuration is the prerequisite that makes the CVE-2026-99312 vulnerability possible.

**「Impact」** Users running nested virtualization on AMD hosts risk having their host memory disclosed by guest VMs until the kernel is updated. The recommended mitigation is to disable nested virtualization until the patch arrives in their distribution.

### [Why Output Caching Doesn&\#x27;t Work in LLM Agents](https://seangoedecke.com/why-output-caching-doesnt-work/) ⭐️ 7.0/10

rss · Sean Goedecke · Nov 21, 00:00

**「Background」** LLM inference economics depend on caching model inputs to avoid recomputing the full conversation history for each message. Output caching might seem promising to prevent repetitions in agent outputs, such as code snippets or quoted evidence documents, which are more expensive to produce than inputs.

**「Solution」** The author proposes fine-tuning or prompting models to output references to history segments \(for example, &quot;src/script.py:12-15&quot;\) instead of full repetitions, with the harness expanding those references transparently for the user. However, this only optimizes the visible output, which the author estimates at about 6% of total tokens based on agent histories—50% reasoning tokens and 44% tool calls. This is limited by Amdahl&\#x27;s law, since even optimistic savings of two-thirds on the visible fraction would save only 4% of total output tokens. True savings require reducing the 94% invisible tokens through smarter models that need fewer reasoning steps and tool calls, which is why more expensive models can sometimes be cheaper overall.

**「Takeaway」** Output caching won&\#x27;t deliver meaningful savings because most tokens are invisible to the user. The real optimization comes from intelligent models and harnesses that minimize unnecessary reasoning and tool use.
